# ADAPT

<!-- impeccable:product-schema 1 -->

## Platform
web

## Stack
React, TypeScript and Vite, as specified in ADAPT v2.4.3. The backend team owns FastAPI, DuckDB and the world service.

## Users
D2C growth managers reviewing advertising decisions, and hackathon judges following the decision loop.

## Product Purpose
Make budget decisions inspectable: data → detection → probable diagnosis → allocation → human approval → verified execution → outcome feedback.

## Capabilities and Constraints
Stage 1 has Command Center, Decision Center and Scenario Lab; Meta and Google; PROFIT objective; Approve mode only. The next frontend slice adds Anomalies, Optimizer, Execution & Ledger and Backend Connection as an explicitly labelled fixture workbench with provisional API adapters. It does not establish that the Stage 2 backend gate has passed. Inventory uses deterministic projected stock shortfall. No production autonomy or causal proof is claimed. Source values have lineage and provenance. Backend decisions own mathematics, policy, hashes and lifecycle. Custom fixture allocation revisions remain non-executable drafts until backend valuation exists. Settings restoration cannot undo incurred spend.

## Evidence on Hand
User-supplied ADAPT v2.4.3 engineering specification. The backend foundation now exists; its FastAPI application currently exposes health only. Bundled frontend fixtures are illustrative UI examples, not engine output, evaluation evidence or seed-42 simulator results. The connection page validates configured backend read responses without substituting fixtures.

## Brand Commitments
ADAPT: Autonomous Decision & Allocation Platform for D2C.

## Product Principles
Show evidence before action. Distinguish forecasts from measured outcomes. Never silently replace a failed API with fixtures. Require explicit approval for a particular decision hash.
