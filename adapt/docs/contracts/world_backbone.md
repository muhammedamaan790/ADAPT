# Contract: world backbone (A1 subset) and data-reality decisions

Module: `world/world/backbone.py` · CLI: `uv run python -m world.backbone --raw-dir data/raw --out data/world/backbone`

## INPUT
TheLook raw CSVs (`data/raw/thelook/`): products, orders, order_items, events, users. Read-only; never modified
(test: raw file hashes unchanged after extraction).

## OUTPUT
`data/world/backbone/*.parquet` + `manifest.json` (window, config, per-table row count and content sha256).

| Table | Grain | Notes |
|---|---|---|
| categories | (department, category) | top N by non-cancelled revenue in the window; `category_code` e.g. `M_OUTERWEAR_COATS` |
| product_sku | TheLook product | every product of a promoted category -> exactly one price-band SKU |
| skus | SKU | `units_window`, `unit_price`, `unit_cogs`, `return_rate` from window lines (catalogue price if never sold) |
| orders, order_items | order / line | all categories (store-wide); `sku` NULL = unmapped (warehouse) |
| sessions | session | aggregated from events: source, landing URI, purchased, product views |
| users | user | users with a window order or session |

## ALGORITHM
- Window = last `window_days` complete days in Asia/Kolkata, ending the day before the last order date.
- Orders are windowed by order `created_at` (IST date); items follow their order (never split).
- Categories ranked by revenue excluding `Cancelled` lines; ties by department, category.
- SKU band = `ntile(groups_per_category)` over (department, category) ordered by (retail_price, product id).

## PARAMETERS (defaults)
`window_days=365`, `n_categories=12`, `groups_per_category=5` (-> 60 SKUs).

## Measured on the real data (2023-01-18 .. 2024-01-17)
66,324 orders · 96,127 lines · 195,473 sessions · 48,475 users · 12,285 promoted products in 60 SKUs.
Promoted SKUs cover 57% of store revenue. SKU gross margin 0.40–0.60, return rate 8.8%–15.9%,
291–1,292 units per SKU per year.

## Data-reality decisions (each corrects an assumption in the spec, §1)
1. **SKU = price-band style group, not a single TheLook product.** The best-selling product sells 14 units a
   year; mapping campaigns to "top 5 products" would leave ~97% of their revenue unmapped (every campaign
   MIX_UNCERTAIN) and give inventory risk nothing to act on.
2. **Category = (department, category).** TheLook categories such as Jeans exist in Men and Women.
3. **The ad funnel is built backward from purchases, not from TheLook sessions.** Every TheLook traffic source
   converts at ~49% of sessions (real e-commerce: 1–3%), so sessions are not a usable click proxy.
   Construction: clicks = purchases / CVR, impressions = clicks / CTR, spend = impressions x CPM / 1000,
   sessions = clicks x click->session rate, with CTR/CVR/CPM drawn from the Global Ads **E-commerce** rows per
   platform (medians: Meta CTR 2.45%, CVR 4.5%, CPM $29; Google CTR 3.9%, CVR 4.6%, CPM $77).
4. **No discounts in history.** `sale_price == retail_price` on all 181,759 lines, so discount = 0 in the
   backbone; price changes come from SCD2 price scenarios (S4).
5. **ERP stock is simulated (CALIBRATED), not read from inventory_items.** TheLook receives 490k units and sells
   182k, so stock never runs out. The world runs an (s, Q) replenishment policy calibrated to backbone demand.
6. **History is generated by the world model, calibrated to TheLook; brand volume scale k.** At native scale a
   campaign gets ~1.6 paid orders a day, too few for DEMO_01 maturity (>= 100 orders in 3 days) or eligibility
   thresholds. TheLook supplies the catalog, prices, costs, return rates, SKU mix, the daily demand profile
   per category, and the traffic-source purchase shares; the world then simulates the 365 history days with the
   same process it uses after day 0, at k x TheLook's volume. One process for history and future means no
   regime break at "today". Store records are labelled CALIBRATED; the catalog/economics stay PUBLIC-SAMPLE.
   k is the smallest value for which DEMO_01 matures in 3 days on seed 42 (CI-checked); default 10.
   See `world_truth.md`.
7. **History end date is a seed parameter, not wall-clock "yesterday".** A fixed anchor keeps seed runs
   reproducible; the demo seeds with `history_end_date = yesterday` and records it in the seed config.

## FAILURE STATES
Missing raw file or empty orders -> error (no partial output). M0 `profile.py` gate runs first.

## TESTS
